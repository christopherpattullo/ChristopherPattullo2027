WireBend-Kit — Angle Feedback

Closing the loop on a wire-bending fabrication machine by adding electronic angle sensing and a correction pass — turning an open-loop machine into a repeatable tool.

Python Embedded C Control Systems Research Programmable Matter Lab

Context

WireBend-Kit is a research machine built at the UW Programmable Matter Lab (advisor: Professor Martin Nisser) that automatically bends wire into 3D shapes from a digital design. A user specifies a sequence of bend angles, and the machine actuates the wire through a series of forming passes.

The problem when I joined the project was repeatability. Metal wire springs back after bending — the "springback" angle depends on material properties, work-hardening from previous bends, and slight variations in wire diameter. The machine was issuing commands based on a fixed kinematic model, but the actual output angles drifted, and errors accumulated across a sequence of bends.

The feedback system

Sensing

I added electronic angle sensing at the bend point. The sensor reads the actual bend angle after each actuation. The key challenge in sensing is that the wire is under mechanical stress and the sensing geometry changes as the wire deforms, so I needed a sensor placement and design that remained reliable across the full range of bend angles the machine produces.

Control loop

After each bend, the firmware reads the sensor, computes the error between the target angle and the measured angle, and decides whether to command a correction pass. This is a simple proportional correction — not a full PID controller, because the actuator dynamics are slow enough that integral and derivative terms didn't meaningfully improve response. The correction logic had to account for the fact that overbending and then correcting back introduces more work-hardening than getting it right the first time, so the correction magnitude is deliberately conservative.

Firmware consolidation

The original machine split its control across multiple microcontrollers, which made it difficult to reason about timing and added latency between the sensing and actuation steps. I refactored the firmware to run on a single controller, which simplified the architecture considerably and reduced the feedback loop latency.

Python GUI and tooling

The machine is controlled through a Python GUI that I rewrote to make iterative testing faster. The old interface required navigating through multiple screens to issue a single bend command; the new one surfaces the most common operations on the main panel and adds a single-command mode where you can quickly test a specific angle without building a full sequence. This made it much faster to characterize how the machine behaved at different angles and materials.

Key challenges

The trickiest part was characterizing the springback behavior. Metal wire doesn't spring back the same amount every time — the amount depends on how much the wire has already been worked. An over-corrected bend followed by a reverse correction adds more hardening than a single accurate bend, and the accumulated error changes the springback coefficient for future bends in the sequence. Getting the correction logic right required building a model of how springback evolves across a sequence rather than treating each bend independently.

What I'd do differently

I'd invest more time in modeling the material behavior up front rather than tuning the correction gain empirically. A proper material characterization — measuring springback as a function of bend angle and prior work history — would let the controller adapt automatically to different wire types without manual re-tuning.
